STEP 12.1 — LEARN THE 5 WORDS (no code here, just understanding)
================================================================================

Think of it like a phone call vs an SMS:

  SOCKET
  -------
  It's like a phone call that STAYS OPEN between one browser tab and the server.
  Either side can say something at any time without dialing again.
  Example: you open the chat app → a socket opens. You close the tab → it closes.

  ROOM
  ----
  A named group of sockets. Like a group phone call.
  When the server says something to a room, EVERYONE in that room hears it.

  In your app you'll use two kinds of rooms:
    • One room per conversation → named after the conversation's UUID
      Example: room name = "conv_abc123"
      Everyone in that chat room sees new messages instantly.
    • One room per user → named after the user's UUID
      Example: room name = "user_xyz789"
      Used for notifications that follow you wherever you are in the app.

  NAMESPACE
  ---------
  A separate channel on the same connection.
  Like having different departments at a company — same building, different floors.
  You will use the DEFAULT namespace (the "/" one). Do NOT create more.

  ACKNOWLEDGEMENT (ack)
  ---------------------
  A callback reply: "did you receive this?"
  Example:
    Client sends: "please save this message"
    Server saves it to database
    Server replies back to ONLY that client: "yes, saved! here is the saved message"
  This is how the sender knows the message was truly stored.

  MIDDLEWARE (socket version)
  ---------------------------
  Code that runs ONCE when a socket tries to connect, BEFORE anything else.
  This is where you check: "does this person have a valid login token?"
  If yes → let them in.
  If no → refuse the connection.

STEP 12.4 — BUILD THE SOCKET AUTH MIDDLEWARE
================================================================================

WHAT IS HAPPENING HERE?
  Before the socket is allowed to do ANYTHING, you check their login token.
  This runs once per connection attempt, before any event listeners are active.

  It's like a bouncer at the door:
    "Show me your ID (token) → valid → come in → connected"
    "Show me your ID (token) → invalid → sorry, go away → rejected"

WHERE DOES THE TOKEN COME FROM?
  The browser sends it in the "auth" field when creating the socket:
    const socket = io("http://localhost:4000", { auth: { token: "the_token_here" } });

  On the server you read it from:
    socket.handshake.auth.token

  WHY NOT FROM THE URL?
    Because URLs appear in server logs, browser history, and CDN logs.
    Your token would be visible to anyone who reads those logs.

─────────────────────────────────────────────────────────────────────────────
ACTION 1: Create a new folder and file
  Create folder:  src/realtime/middleware/

────────────────── PASTE THIS INTO src/realtime/middleware/socketAuth.ts ────

import type { Server, Socket } from "socket.io";
import { verifyAccessToken } from "../../utils/token.js";

/**
 * Socket.IO middleware: checks that the connecting client has a valid
 * access token in socket.handshake.auth.token
 *
 * On success: attaches user info to socket.data so every handler can
 *             read socket.data.userId and socket.data.username safely.
 *
 * On failure: calls next(error) which refuses the connection.
 */
export function socketAuthMiddleware(socket: Socket, next: (err?: Error) => void): void {
  // Step 1: Read the token from the auth field (NOT from query string!)
  const token = socket.handshake.auth?.token as string | undefined;

  // Step 2: Is there even a token?
  if (!token) {
    return next(new Error("AUTH_MISSING: No token provided"));
  }

  // Step 3: Verify the token using the SAME helper the REST routes use
  const result = verifyAccessToken(token);

  // Step 4: If verification failed, refuse the connection
  if (!result.ok) {
    return next(new Error(`AUTH_INVALID: ${result.error}`));
  }

  // Step 5: Token is good! Attach user info to socket.data
  // From now on, every event handler reads socket.data.userId
  // and socket.data.username — they NEVER trust what the client sends
  // inside an event payload for identity.
  socket.data.userId   = result.payload.sub;      // the user's UUID
  socket.data.username = result.payload.username; // the user's display name

  console.log(`Socket authenticated: ${socket.data.username} (${socket.id})`);

  // Step 6: Let the connection proceed
  next();
}

STEP 12.6 — MAKE EVERY HANDLER SAFE (ERROR WRAPPER)
================================================================================

THE PROBLEM:
  In Express, if a handler throws an error, Express catches it automatically.
  In Socket.IO, if a handler throws, it can CRASH YOUR ENTIRE SERVER.
  There is no automatic protection.

THE SOLUTION:
  Wrap every socket handler in a try/catch.
  If something goes wrong → send an error event back to that specific socket.
  The server stays alive and the client gets a clear message.

─────────────────────────────────────────────────────────────────────────────
ACTION: Create file  src/realtime/handlers/utils.ts
─────────────────────────────────────────────────────────────────────────────

────────────────── PASTE THIS INTO src/realtime/handlers/utils.ts ───────────

import type { Socket } from "socket.io";
import { ServerEvents } from "../events.js";

/**
 * Wraps an async socket handler in error protection.
 *
 * Usage:
 *   socket.on("message:send", safeHandler(socket, async (payload) => {
 *     // your logic here — if it throws, the error is caught automatically
 *   }));
 *
 * On error:
 *   • Emits "error" event back to the socket with a code and message
 *   • Logs full error on the server (for debugging)
 *   • Server process STAYS ALIVE
 */
export function safeHandler<T>(
  socket: Socket,
  handler: (payload: T) => Promise<void>,
): (payload: T) => void {
  return (payload: T) => {
    handler(payload).catch((err: unknown) => {
      // Log the full error server-side (you see this, client doesn't)
      console.error(`Socket handler error [${socket.id}]:`, err);

      // Extract a friendly message
      const message = err instanceof Error ? err.message : "An unexpected error occurred";

      // Send a structured error event back to THIS socket only
      socket.emit(ServerEvents.ERROR, {
        code:    "HANDLER_ERROR",
        message,
      });
    });
  };
}

/**
 * Helper to emit a specific error code back to a socket.
 *
 * Usage:
 *   emitError(socket, "NOT_MEMBER", "You are not part of this conversation");
 */
export function emitError(socket: Socket, code: string, message: string): void {
  socket.emit(ServerEvents.ERROR, { code, message });
}

  });

  console.log("Socket.IO server created");

  // ── Auth middleware (runs before any event) ──────────────────────────────
  io.use(socketAuthMiddleware);

  // ── Handle new connections ───────────────────────────────────────────────
  io.on("connection", (socket) => {
    console.log(`✓ ${socket.data.username} connected [${socket.id}]`);

    // Register all handlers — one function per topic
    registerPresenceHandlers(io, socket);
    registerMessageHandlers(io, socket);
    registerTypingHandlers(io, socket);
    registerReceiptHandlers(io, socket);
    registerSyncHandlers(io, socket);
  });

  return io;
}

export function getIo(): Server {
  if (!io) {
    throw new Error("Socket server not initialised. Call initSocketServer() first.");
  }
  return io;
}
